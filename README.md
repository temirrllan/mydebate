## 1. Что это

**MyDebate** — веб-платформа (Казахстан), объединяющая **дебатные турниры** и **MUN-конференции**: поиск, публикация, регистрация участников, история участия, модерация и админ-панель. Это **MVP** для проверки Product-Market Fit. Все 8 этапов (0–7) завершены — приложение функционально готово.

Язык интерфейса — русский. Дизайн: бренд-синий `#2563EB`, тёмно-navy hero/CTA-блоки, светлый фон, белые скруглённые карточки, чип-бейджи, шрифт Inter.

## 4. Как запустить

Все команды — **из папки `web/`** (иначе не резолвятся node_modules/алиасы).

```bash
cd web
npm install            # установить зависимости (первый раз)
npm run dev            # dev-сервер → http://localhost:3000
```

Прочие команды:

```bash
npm run build          # продакшн-сборка (Turbopack + typecheck)
npm run start          # запустить собранное
npm run lint           # ESLint
npm run db:seed        # залить/пересоздать демо-данные (идемпотентно)
```

### Первый запуск с нуля (если БД пустая)
```bash
cd web
npx prisma migrate dev   # применить миграции, создать dev.db
npm run db:seed          # залить демо-данные
npm run dev
```

### `.env` (уже настроен для локалки)
Ключи: `DATABASE_URL` (путь к SQLite), `AUTH_SECRET` (секрет NextAuth), `AUTH_URL` / `NEXTAUTH_URL` (базовый URL). Файл `.env` не в гите — при переносе на другую машину его нужно создать заново.

## 6. Роли и права

Роли повышаются автоматически: **Гость → Пользователь → Организатор → Админ**.

- **Гость** (не авторизован) — по ТЗ строго: **НЕ видит каталог турниров**, редиректится на вход. Доступны только лендинг и инфо-страницы.
- **Пользователь (USER)** — каталог, поиск/фильтры, регистрация на турнир, избранное, профиль, создание турнира.
- **Организатор (ORGANIZER)** — то же + управление своими турнирами: редактирование (описание/разделы), список участников. **Роль присваивается автоматически** после того, как первый созданный им турнир одобрен модерацией (`maybePromoteToOrganizer`).
- **Админ (ADMIN)** — модерация турниров, управление пользователями/организаторами, обращения в поддержку.

## 7. Карта роутов

### Публичные (доступны гостю)
`/` (главная) · `/about` · `/contacts` · `/help` · `/rules` · `/privacy` · `/terms` · `/login` · `/register` · `/forgot-password` · `/reset-password` · `/403`

### Требуют входа (любая роль; гость → `/login`)
- `/tournaments` — каталог (поиск, фильтры формат/тип/город/уровень/дата, пагинация)
- `/tournaments/[id]` — страница турнира
- `/tournaments/[id]/register` — регистрация на турнир (внутренняя форма; для EXTERNAL-турниров кнопка ведёт на сайт организатора)
- `/tournaments/create` — мастер создания турнира (3 шага → на модерацию)
- `/tournaments/[id]/edit` — **редактирование (только владелец-организатор):** описание, обложка/логотип, разделы. Даты/цена/место — только через поддержку.
- `/tournaments/[id]/participants` — **список участников (только владелец):** снимок данных заявок
- `/profile` — кабинет: вкладки `?tab=` (мои турниры, заявки, избранное, уведомления, о себе, настройки)

### Только ADMIN (не-ADMIN → `/403`)
- `/admin` — дашборд (счётчики)
- `/admin/moderation` — очередь модерации турниров
- `/admin/users` — пользователи
- `/admin/organizers` — организаторы
- `/admin/support` — обращения в поддержку

### API
- `/api/auth/[...nextauth]` — эндпоинты NextAuth
- `/api/uploads/tournament-image` — загрузка обложки/логотипа (POST, до 5 МБ, jpeg/png/webp, только авторизованным)

## 8. Что умеет админ-панель

Зайти: см. [раздел 5](#5--тестовые-аккаунты-и-вход-в-админ-панель).

- **Обзор** (`/admin`) — карточки-счётчики: пользователи, организаторы, турниры (с разбивкой на модерации / опубликовано / скрыто), заявки, открытые обращения. Акцентные карточки «на модерации» и «открытые обращения» — быстрые ссылки в разделы.
- **Модерация** (`/admin/moderation`) — очередь турниров (по умолчанию статус PENDING), фильтр по статусу + поиск, пагинация. По каждому турниру действия:
  - **Одобрить** → турнир PUBLISHED, появляется в каталоге, автору уведомление, **роль автора USER→ORGANIZER автоматически**.
  - **Отклонить** (с обязательной причиной) → турнир скрыт (HIDDEN + причина), автору уведомление с причиной.
  - **Скрыть** (для опубликованного) → убрать из каталога без причины.
  - **Удалить** → мягкое удаление (статус DELETED, регистрации сохраняются). Подтверждение — инлайн «Точно удалить?».
- **Пользователи** (`/admin/users`) — поиск/фильтр по роли, блокировка/разблокировка (заблокированного мгновенно выкидывает из сессии), удаление. Кнопки заблокированы для самого себя и других ADMIN.
- **Организаторы** (`/admin/organizers`) — список тех, кто публикует турниры, со статистикой по статусам.
- **Обращения** (`/admin/support`) — тикеты из формы `/contacts`. Ответить (→ ANSWERED + уведомление автору) или закрыть (→ CLOSED).

> Соглашение: **«Отклонён» = статус HIDDEN + заполненное поле `rejectionReason`** (в статусах нет отдельного REJECTED). Отображается через `getTournamentStatusDisplay` в `lib/format.ts`.

## 9. База данных

**Модели** (`web/prisma/schema.prisma`): `User`, `Tournament`, `TournamentSection`, `Registration`, `Favorite`, `Notification`, `SupportTicket` + NextAuth-таблицы (`Account`, `Session`, `VerificationToken`, `PasswordResetToken`).

**Особенности SQLite:** нет нативных `enum` и `String[]`. Все «перечисления» — строковые поля + TS-константы в `lib/enums.ts`. Языки хранятся строкой через запятую (`"Русский,English"`) — хелперы `parseLanguages`/`formatLanguages`.

**Демо-данные после seed:** 3 пользователя (см. [раздел 5](#5--тестовые-аккаунты-и-вход-в-админ-панель)), 11 турниров (10 PUBLISHED в разных состояниях + 1 PENDING на модерации), у одного турнира — 6 комитетов, плюс регистрации, избранное, уведомления и 1 обращение.

Пересоздать чистые демо-данные в любой момент: `cd web && npm run db:seed`.

## 10. Гочи Next 16 — на что не наступить

- **Async Request APIs:** `params`, `searchParams`, `cookies()`, `headers()` — теперь Promise, всегда `await`.
- **`middleware.ts` → `proxy.ts`** — конвенция переименована. Ролевые гейты в `web/proxy.ts`.
- **Turbopack по умолчанию** для `next dev` и `next build`.
- **Tailwind v4:** дизайн-токены в `app/globals.css` через `@theme`, а не в `tailwind.config.js`.
- **Prisma 7:** клиент импортируется как `@/generated/prisma/client`; нужен driver-adapter (better-sqlite3); singleton уже готов в `lib/prisma.ts`. Скрипты запускать **из `web/`**.
- **`"use server"`-файлы не экспортируют лишние константы** — тексты сообщений держим в `lib/format.ts`.
- Подробнее: `web/AGENTS.md` и локальные доки в `web/node_modules/next/dist/docs/`.

## 11. Статус и бэклог

**Готово:** все этапы 0–7 (каркас → данные → авторизация → публичные страницы → ядро пользователя → создание турниров → модерация+админка → полировка). Сборка и линт зелёные, сквозная QA пройдена. Детали — в [[progress]] и [[tasks]].

**Осознанно вне MVP:**
- Kaspi-оплата / шаг чека при регистрации (отложено по договорённости с заказчиком)
- Google OAuth (кнопка есть, но провайдер заглушён — нет тестовых креденшелов)
- Глубокий аудит доступности (был только спот-чек)
- Продакшн-деплой + миграция SQLite → Postgres
