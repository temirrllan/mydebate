# Гайд по развёртыванию MyDebate — что создавать и зачем

Дата: 2026-08-09. Связано: [[deploy]] (краткий чеклист), [[PLAN]], [[progress]].
Тэги: #deploy #reference

Этот файл отвечает на вопрос «зачем вообще столько сервисов, я же раньше просто пушил на сервер». Короткий ответ: раньше у тебя была **одна машина**, где лежало всё сразу. Vercel — не машина. Ниже подробно.

---

## 0. Почему «просто запушить» здесь не работает

Как было на обычном хостинге/VPS:

> Есть сервер. На нём папка с кодом, рядом крутится Postgres, рядом папка `uploads` на диске. Ты пушишь код, перезапускаешь процесс — всё работает. База и файлы живут на том же диске и никуда не деваются, потому что диск постоянный.

Как устроен Vercel:

> Постоянной машины нет. На каждый запрос поднимается временный контейнер с твоим кодом, отвечает и умирает. Диск у него **только для чтения**, а то, что удалось записать во временную папку, исчезает вместе с контейнером. Никакой базы «рядом» не существует.

Отсюда и вылезают три вещи, которых раньше не было:

| Что | Раньше | Теперь |
| --- | --- | --- |
| База данных | Postgres на том же сервере | Отдельный сервис (Neon), приложение ходит к нему по сети |
| Загруженные картинки | Папка `uploads` на диске | Отдельное хранилище (Vercel Blob) |
| Секреты (пароли, ключи) | Файл `.env` на сервере | Переменные окружения в панели Vercel |

Это не усложнение ради усложнения — это плата за то, что не надо администрировать сервер: не настраиваешь nginx и TLS, не следишь за местом на диске, не обновляешь систему, деплой идёт сам из git.

**Важно: старый способ никуда не делся.** Если тебе привычнее одна машина — бери VPS, там всё будет ровно как ты помнишь (раздел 6). Код это уже поддерживает: если переменной `BLOB_READ_WRITE_TOKEN` нет, загрузчик пишет картинки на обычный диск, как раньше. Выбирай осознанно, оба пути рабочие.

## 1. Из чего состоит развёртывание

Четыре кубика. Что каждый делает и что сломается без него:

1. **Хостинг приложения (Vercel).** Собирает код из git и отдаёт сайт пользователям. Без него сайта просто нет.
2. **База данных (Neon Postgres).** Пользователи, турниры, заявки, уведомления, обращения в поддержку. Без неё приложение стартует, но падает на первом же запросе к данным.
3. **Хранилище файлов (Vercel Blob).** Сами файлы обложек и логотипов. В базе хранится только *ссылка* на картинку. Без Blob на Vercel файл записать некуда — ссылка в базе будет, а картинки по ней не будет.
4. **Переменные окружения.** Как приложение узнаёт адрес базы, ключ подписи сессий, доступы к Google и почте. Без них приложение не поднимется вообще.

Плюс два внешних сервиса, которые уже частично настроены: **Google OAuth** (вход через Google) и **SMTP** (письма).

## 2. База данных: Neon

### Почему две строки подключения, а не одна

Это единственное неочевидное место во всём гайде, поэтому подробно.

На Vercel твоё приложение живёт не одним процессом, а десятками короткоживущих. Каждый открывает своё соединение с базой. У Postgres лимит одновременных соединений (на бесплатных планах — небольшой), и его быстро выносит. Поэтому между приложением и базой ставят **пулер** — прослойку, которая держит немного реальных соединений и раздаёт их всем желающим по очереди.

Но у пулера есть режим (transaction mode), в котором **не работают миграции**: им нужно выполнить несколько команд в одной непрерывной сессии и подержать блокировку, а пулер сессию не гарантирует. Поэтому:

- `DATABASE_URL` → **пулерная** строка, её использует приложение в бою (`web/lib/prisma.ts`);
- `DIRECT_URL` → **прямая** строка, её использует Prisma CLI для миграций и seed (`web/prisma.config.ts`).

У Neon они отличаются одной вставкой `-pooler` в имя эндпоинта:

```
пулерная:  postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ep-ИМЯ-pooler.c-5.РЕГИОН.aws.neon.tech/neondb?sslmode=require
прямая:    postgresql://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ep-ИМЯ.c-5.РЕГИОН.aws.neon.tech/neondb?sslmode=require
```

`?sslmode=require` в конце обязателен — Neon не принимает незашифрованные подключения.

### Что делать

- [ ] Зарегистрироваться на neon.tech, создать проект.
- [ ] **Регион — европейский** (`eu-central-1`, Франкфурт), если пользователи в Казахстане и СНГ. Регион потом не меняется без переезда базы, а разница ощутимая: до Огайо каждый запрос к базе идёт лишние ~150–200 мс, и на одной странице их обычно несколько.
- [ ] Версия Postgres — дефолтная.
- [ ] **Neon Auth — не включать.** Это отдельный провайдер входа, а у нас уже свой: NextAuth с email+паролем и Google, свои таблицы `User`/`Account`/`Session`, роли, брутфорс-защита. Neon Auth завёл бы второй, никем не используемый источник правды о пользователях.
- [ ] Скопировать обе строки подключения (переключатель «Pooled connection» на экране подключения).

⚠️ Строки подключения содержат пароль от базы. Не вставляй их в чаты, не коммить в git, не клади в скриншоты. Если засветил — сбрось пароль роли в настройках Neon, старая строка сразу перестанет работать.

## 3. Хостинг: Vercel

- [ ] Зарегистрироваться через GitHub, импортировать репозиторий `temirrllan/mydebate`.
- [ ] **Root Directory = `web`** — критично. Приложение лежит не в корне репозитория, и без этого сборка не найдёт `package.json`.
- [ ] Framework Vercel определит сам (Next.js). Команды сборки не трогать — `prisma generate` уже прописан в `package.json`.
- [ ] Переменные окружения (Settings → Environment Variables), окружение **Production**:

| Переменная | Значение | Что будет без неё |
| --- | --- | --- |
| `DATABASE_URL` | пулерная строка Neon | приложение падает на любом обращении к данным |
| `DIRECT_URL` | прямая строка Neon | не пройдут миграции |
| `AUTH_SECRET` | `openssl rand -base64 32` — **новый**, не локальный | сессии не подписываются, вход не работает |
| `AUTH_URL` | `https://твой-домен` | вход падает, ссылки в письмах ведут на localhost |
| `AUTH_GOOGLE_ID` | из Google Cloud Console | не работает вход через Google |
| `AUTH_GOOGLE_SECRET` | оттуда же | то же |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASSWORD` | доступы к почте | письма не уходят (приложение не падает — пишет письмо в лог) |
| `EMAIL_FROM` | `MyDebate <адрес>` | письма уйдут от адреса SMTP-пользователя |

Про `AUTH_SECRET`: это ключ, которым подписываются сессии. Кто им владеет — может выписать себе сессию любого пользователя, включая админа. Поэтому на проде он обязан отличаться от локального.

- [ ] Запустить деплой, дождаться зелёного билда.

**После этого шага сайт уже открывается, но базы в нём ещё нет** — таблицы не созданы. Это следующий шаг.

## 4. Создать таблицы (миграции)

Деплой **не создаёт таблицы сам** — это делаешь ты, один раз, со своей машины:

```
cd web
DIRECT_URL="<прямая строка Neon>" npx prisma migrate deploy
```

- Переменную передаём прямо в команде, а не через `.env` — так прод-доступ не осядет в файле и не перезапишет локальную настройку.
- Именно `migrate deploy`, **не `db push`**: первый применяет подготовленные миграции и ведёт историю, второй подгоняет схему «как получится» и умеет молча удалять данные. На проде — только `deploy`.

Проверить глазами, что таблицы появились:
```
DIRECT_URL="<прямая строка>" npx prisma studio
```
Откроется локальный интерфейс к прод-базе — там должны быть `User`, `Tournament`, `Registration` и остальные.

## 5. Первый администратор

⚠️ **`npm run db:seed` на прод не запускать.** Сид сначала удаляет все данные во всех таблицах, а потом создаёт демо-пользователей с паролем `password123`, включая `admin@mydebate.kz`. На живом сайте это снесёт данные и оставит админку с общеизвестным паролем.

Правильный путь:

- [ ] Зарегистрироваться на сайте обычной формой — создастся пользователь с ролью `USER`.
- [ ] Открыть Studio на прод-базу, найти себя в таблице `User`, поменять `role` на `ADMIN`.
- [ ] Всё остальное — уже из админки сайта.

## 6. Хранилище картинок

- [ ] В проекте Vercel → Storage → создать **Blob**-стор, подключить к проекту.
- [ ] `BLOB_READ_WRITE_TOKEN` появится в переменных сам.
- [ ] Сделать редеплой, чтобы приложение его увидело.

Как это работает в коде (`web/app/api/uploads/tournament-image/route.ts`): токен есть → файл уходит в Blob, и в базу пишется абсолютный URL; токена нет → файл пишется в `public/uploads`, как на обычном сервере. Второй режим нужен для локальной разработки и для VPS.

---

## 7. Проверка, что всё действительно сохраняется

Главный тест — **пережить редеплой**. Пока не проверил его, считать развёртывание рабочим нельзя.

- [ ] Зарегистрировать пользователя → он появился в `User` в Studio.
- [ ] Создать турнир с обложкой → турнир виден в каталоге, картинка отображается.
- [ ] Нажать Redeploy в Vercel, дождаться, открыть турнир снова.
- [ ] Данные на месте **и** картинка на месте → Postgres и Blob подключены правильно.
- [ ] Данные есть, а картинка пропала → не подхватился `BLOB_READ_WRITE_TOKEN`.
- [ ] Прогнать сценарии по ролям: гость / пользователь / организатор / админ (модерация, заявки, уведомления).

## 8. Альтернатива: VPS — «как раньше»

Если ближе привычная схема «одна машина, всё на ней»:

- VPS за ~5 $/мес, на нём Docker Compose: Next.js (`output: "standalone"`), Postgres, Caddy для HTTPS.
- Картинки — в папку на постоянном диске (volume), Blob не нужен: без `BLOB_READ_WRITE_TOKEN` код сам работает в этом режиме.
- Neon не нужен — Postgres стоит рядом в контейнере.
- Переменные окружения — в `.env` на сервере, как ты привык.

Что взамен: TLS-сертификаты, бэкапы базы, обновления системы, мониторинг и перезапуск после падений — на тебе. Деплой не «сам из git», а руками или через свой скрипт.

Что выбрать: **Vercel** — если хочется сосредоточиться на продукте и не трогать инфраструктуру. **VPS** — если хочется полный контроль и знакомый процесс, и не жалко времени на обслуживание.

➡️ **Выбран этот путь (2026-08-09).** Обвязка написана и лежит в репозитории: `web/Dockerfile`, `docker-compose.yml`, `Caddyfile`, `.env.production.example`, `deploy/backup.sh`. Пошаговая инструкция по серверу — в [[deploy-vps]].

Побочный эффект для локальной разработки: в `next.config.ts` включён `output: "standalone"`, из-за чего `npm start` печатает предупреждение «does not work with output: standalone» (страницы при этом отдаёт). Локально пользуйся `npm run dev`, а прод-режим проверяй через `node .next/standalone/server.js`.

## 9. Частые ошибки и что они значат

| Симптом | Причина |
| --- | --- |
| `Can't reach database server` | нет `?sslmode=require`, опечатка в строке или база спит (первый запрос после простоя) |
| Миграция висит или `prepared statement already exists` | миграции запущены по пулерной строке вместо прямой |
| `UntrustedHost` при входе | не задан `AUTH_URL` |
| `redirect_uri_mismatch` у Google | в Cloud Console не добавлен `https://<домен>/api/auth/callback/google` |
| Сборка падает на `@/generated/prisma/client` | не тот Root Directory (должен быть `web`) |
| Обложки исчезают после редеплоя | нет Blob-стора или не подхватился токен |
| Все вылетели из аккаунтов после деплоя | сменился `AUTH_SECRET` — это нормально, старые сессии инвалидируются |

> Названия кнопок в интерфейсах Neon и Vercel меняются со временем — ориентируйся на смысл, а не на точные подписи: нужны две строки подключения, переменные окружения и Blob-стор.
