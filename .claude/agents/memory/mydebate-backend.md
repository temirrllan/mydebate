- **Deadline bug fix, `web/lib/format.ts` `isRegistrationOpen`:** `<input
  type="date">` yields `"YYYY-MM-DD"`, which `new Date(...)` parses as UTC

  mutates the input `Date`): `endOfDeadlineDay.getTime() >= Date.now()`.
  Registration is now open through the entire deadline day inclusive, per
  spec. This is the **single shared helper** — every deadline-vs-now
  comparison in the codebase already routed through it (verified via grep:
  `lib/actions/registrations.ts`, `components/tournaments/tournament-card.tsx`,
  `app/tournaments/[id]/page.tsx`, `app/tournaments/[id]/register/page.tsx`)
  so fixing it here was sufficient — no other file had a duplicated raw
  comparison to fix.

  `web/lib/admin/queries.ts` — zero call sites anywhere (verified via grep

- Self-protection and ADMIN-protection guards (`setUserBlocked`, `deleteUser`) check the target's *current* role from a fresh DB read, not any cached/passed-in value — never trust a client-supplied role flag.

**Decisions worth remembering:**
- `editTournament` takes `tournamentId` as a **bound first argument** (`.bind(null, tournamentId)`), not a FormData field — consistent with `registerForTournament`/`cancelRegistration`, and safer than trusting a hidden `<input name="tournamentId">` that a modified client request could tamper with (the bound value comes from the server-rendered page's props, not user-controlled form state).
- `createSupportTicket` uses `getCurrentUser()` (not `requireUser()`) even though the spec text says "by ТЗ обращается авторизованный пользователь" — chosen because the `SupportTicket.userId` field is explicitly nullable in the schema and the task instruction says "если гость — userId null", so a hard redirect-to-login would contradict the model's own designed flexibility; same button/form judgment call as the Этап 4 "form vs button" split, except here it leans toward NOT gating since the schema itself signals guest support is intentional.
- `TOURNAMENT_CHANGED` notifies **participants** (users with a `Registration` row), not the organizer (the organizer is the one making the edit) — distinct from `TOURNAMENT_HIDDEN`/`TOURNAMENT_DELETED`/`TOURNAMENT_REJECTED` which all notify the *organizer* about an *admin* action. Don't conflate the two directions when adding more organizer-vs-participant notifications later.
