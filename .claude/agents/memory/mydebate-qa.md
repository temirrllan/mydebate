Private working memory for the mydebate-qa agent. Read this at the start of every run; append durable facts after finishing.

## Run recipe
- App lives in `web/` (Next.js 16.2.10 + Turbopack). Start: `cd web && npm run dev` -> ready in ~0.3s, serves `http://localhost:3000`. Before starting anything, check if it is already running with a curl to `http://localhost:3000/` -- if a response comes back, it is already up (do not start a second instance, and do not kill it at the end either unless you started it yourself).
- DB is SQLite (`web/dev.db`), already seeded -- no setup needed before testing. Query it directly with better-sqlite3 from Node (already in node_modules) from `web/` -- much faster than trying to load the generated Prisma TS client with plain `node -e` (that fails; the generated client is not a runnable JS entrypoint that way).
- Demo accounts (password `password123` for all): `admin@mydebate.kz` (ADMIN), `organizer@mydebate.kz` (ORGANIZER, display name Erlan Saparov -- is the organizer of ALL seeded tournaments, so organizer-name search cannot be used to prove exclusion between tournaments, only inclusion), `sanzhar@mydebate.kz` (USER, display name Sanzhar Tulegenov).
- Seed data snapshot (2026-07-08 run): 10 PUBLISHED plus 1 PENDING (Debate Academy Cup) tournaments. Two tournaments already have a past registration deadline relative to the system clock that day: Nur-Sultan Schools Debate (deadline 07-01) and Shymkent Debate League (deadline 07-03) -- good ready-made fixtures for closed-registration testing without faking the clock. Online Debate Challenge (deadline 07-21) and Almaty Open Debate (deadline 07-15) are reliably-open fixtures. Re-derive which are past/future relative to the actual current date each run.
- No browser MCP tool is provided in this agent toolset (only Read/Glob/Grep/Bash). To do real browser-driven QA: Playwright may already be installed in `web/node_modules` from a prior run -- check before reinstalling. If missing, install with npm and run the Playwright chromium installer (about 1 minute, network access available). Write throwaway driver scripts as `web/qaN.js` (must live under `web/` so the require resolves), run with plain `node qaN.js`, then delete the qaN.js files afterward. Take screenshots to the scratchpad dir and view them with the Read tool.
- Gotcha: in a JS string literal written via a bash heredoc, raw Windows backslash paths get mangled -- always use forward-slash paths inside the .js script.
- Gotcha: navbar renders a logout form twice (desktop hidden copy plus mobile burger copy), both present in DOM at once -- a bare selector for the submit button throws a Playwright strict-mode violation. Filter by visibility or use nth() per viewport. Same strict-mode trap with a generic submit-button selector on any page that also has the navbar own submit buttons in the DOM -- always scope selectors to a specific form or text.
- Gotcha: clicking a link and immediately reading page.url() right after waitForLoadState networkidle can still report the previous URL if the navigation has not flushed yet. Prefer waitForURL with a pattern, or just re-navigate with page.goto using the link href attribute directly, when a reliable synchronous URL check is needed.
- Gotcha: routes with a loading.tsx (streaming enabled) that call notFound() inside the page component return HTTP 200, not 404 -- Next already flushed the loading shell with a 200 status before the error is thrown deeper in the tree. A genuinely unmatched route still correctly returns 404. Do not be fooled by this when checking whether notFound works -- the UI is correct, only the transport-level status code is wrong.
- Dev server was left running by a previous session when this run started -- did not start or stop it this run. Only stop it if you started it yourself.

## Этап 5 session (2026-07-10) — create-tournament wizard (/tournaments/create)
- Gotcha for driver scripts: Playwright's `page.textContent('body')` in this app picks up the `value="..."` HTML attribute of the catalog search `<input>` (server-rendered from the URL's `?search=` param) as if it were rendered text, giving a false positive for "is this string visible on the page". Use `page.locator('body').innerText()` instead when checking whether a specific tournament title is actually visible/absent — `innerText` correctly reflects only what a user would see and does not pick up input `value` attributes.
- Gotcha: `setInputFiles({ name, mimeType, buffer })` (no real file on disk needed) works fine for testing the upload route including wrong-mimetype and oversized-buffer cases; just make sure to `waitForResponse` on `/api/uploads/tournament-image` (or wait >=1s) before asserting on the resulting error/preview state — a short fixed `waitForTimeout` right after the same page already did a slow prior upload can catch the UI mid "Загрузка…" and produce a false-negative on the error-text assertion.
